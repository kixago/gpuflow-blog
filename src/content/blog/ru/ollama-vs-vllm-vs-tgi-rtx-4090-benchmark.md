Запустить собственную модель — это только половина дела.

После дообучения, о котором подробно рассказано в нашем [руководстве по приватному дообучению LLM](/ru/private-llm-fine-tuning-guide/), встаёт практический вопрос: как эффективно обслуживать модель?

От инференса зависят:

- Стоимость одного токена
- Задержка под нагрузкой
- Эффективность загрузки GPU
- Годится ли потребительское железо для продакшена

В этом бенчмарке сравниваются три популярных стека инференса:

- Ollama
- vLLM
- Hugging Face Text Generation Inference (TGI)

Цель — не выбрать любимчика, а измерить.

## Тестовая среда

**Оборудование**

- GPU: NVIDIA RTX 4090 (24 ГБ видеопамяти)
- CPU: 16‑ядерный потребительский процессор класса Ryzen
- ОЗУ: 64 ГБ DDR5
- Накопитель: NVMe SSD
- CUDA: 12.1
- Драйвер NVIDIA: 550+

**Модель**

- `meta-llama/Llama-3.1-8B`
- Точность: FP16 (без 4‑битной квантизации)
- Контекстное окно: 4096 токенов

**Условия бенчмарка**

- Входной промпт на 512 токенов
- Генерация 128 токенов на выходе
- Жадное декодирование (temperature = 0)
- Без спекулятивного декодирования
- Без тензорного параллелизма
- Только «тёплый» старт (модель загружена до начала замеров)
- 8 параллельных потоков запросов (где поддерживается)

Все тесты проводились на чистой машине без фоновых задач. Каждый результат — среднее по пяти запускам.

## Результаты

### 1. Ollama

Ollama делает ставку на простоту. Установка минимальная, модели скачиваются автоматически.

```bash
ollama run llama3
```

Настроек батчинга и стратегии планирования запросов почти нет.

#### Замеры (RTX 4090, FP16)

- **Пропускная способность, один поток:** 62–74 токена/с
- **Пропускная способность, 8 потоков:** 95–108 токенов/с
- **Задержка первого токена:** 720–980 мс
- **Расход видеопамяти:** 14–17 ГБ

#### Наблюдения

- Загрузка GPU при параллельных запросах колебалась.
- После 4 потоков пропускная способность росла нелинейно.
- Нет настроек для тонкой оптимизации батчинга.

Ollama надёжно работает для локальной разработки и сервисов с небольшим трафиком. При постоянной параллельной нагрузке он не загружает GPU полностью.

---

### 2. vLLM

vLLM создан ради пропускной способности. Его реализация PagedAttention эффективнее использует KV-кеш при параллельных запросах.

Установка:

```bash
pip install vllm
```

Запуск:

```bash
python -m vllm.entrypoints.openai.api_server \
  --model meta-llama/Llama-3.1-8B \
  --dtype float16
```

#### Замеры (RTX 4090, FP16)

- **Пропускная способность, один поток:** 92–104 токена/с
- **Пропускная способность, 8 потоков:** 185–215 токенов/с
- **Задержка первого токена:** 360–480 мс
- **Расход видеопамяти:** 20–22 ГБ

#### Наблюдения

- Под нагрузкой загрузка GPU держалась выше 95%.
- Непрерывный батчинг улучшил масштабирование.
- Задержка оставалась стабильной на всех параллельных потоках.

vLLM показал наибольшую устойчивую пропускную способность на час аренды.

---

### 3. Hugging Face Text Generation Inference (TGI)

TGI — контейнеризованный сервер инференса для продакшена.

```bash
docker run --gpus all \
  -p 8080:80 \
  ghcr.io/huggingface/text-generation-inference:latest \
  --model-id meta-llama/Llama-3.1-8B
```

#### Замеры (RTX 4090, FP16)

- **Пропускная способность, один поток:** 78–88 токенов/с
- **Пропускная способность, 8 потоков:** 150–176 токенов/с
- **Задержка первого токена:** 510–690 мс
- **Расход видеопамяти:** 21–23 ГБ

#### Наблюдения

- Производительность стабильная и предсказуемая.
- Масштабируется лучше Ollama, но хуже vLLM.
- Из-за контейнерной среды выше операционные накладные расходы.

TGI даёт инструменты управления и мониторинга для продакшена, но не выжимает максимум пропускной способности из одной 4090.

## Что это значит для стоимости на арендованных GPU

На маркетплейсах GPU аренда RTX 4090 в сентябре 2026 года стоит примерно $0,30–0,46 в час в зависимости от платформы и спроса. Подробный разбор — в наших статьях:

- [Сравнение цен на аренду GPU в 2026 году](/ru/gpu-rental-pricing-comparison-2026/)
- [Реальная стоимость аренды GPU](/ru/hidden-fees-in-gpu-rental/)

Допустим:

- аренда за $0,45 в час
- 500 000 сгенерированных токенов
- 8 параллельных потоков

По медианной измеренной пропускной способности:

**vLLM (~200 токенов/с)**  
500 000 / 200 = 2500 секунд ≈ 41–42 минуты  
Стоимость ≈ $0,31

**Ollama (~100 токенов/с)**  
500 000 / 100 = 5000 секунд ≈ 83–84 минуты  
Стоимость ≈ $0,63

Сама по себе разница невелика. Но с ростом масштаба она накапливается.

При 50 миллионах токенов в день эффективность напрямую влияет на то, сколько GPU и сколько часов аренды вам понадобится.

### Как повторить этот бенчмарк

Чтобы воспроизвести замеры, нужна машина под вашим контролем, где можно установить и настроить каждый сервер. Для этого подойдут маркетплейсы, которые сдают контейнеры с доступом по SSH, например Vast.ai или RunPod.

Если вы хотите просто попробовать модели на Ollama на RTX 4090 без всякой настройки, провайдеры [GPUFlow](https://gpuflow.app/ru/marketplace) запускают Ollama, а вы арендуете доступ через API-ключ, совместимый с OpenAI, с посекундной тарификацией. Сменить сервер инференса там нельзя, так что это вариант для работы с моделями, а не для сравнения серверов.

Поскольку аренда почасовая, эффективность инференса напрямую влияет на стоимость. На постоянной нагрузке разница между 100 и 200 токенами в секунду становится ощутимой.

## Контекст развёртывания

Если вы арендуете GPU почасово, эффективность инференса напрямую определяет эффективность затрат. Мы разбираем расчёты в статье [почасовой GPU или API с оплатой за токены](/ru/hourly-gpu-vs-per-token-api/).

От пропускной способности зависят:

- Сколько часов аренды нужно на задачу
- Сколько GPU нужно под ваш трафик
- Насколько вы зависите от нестабильности хоста
- Операционная маржа

С эффективным стеком инференса потребительские GPU остаются экономически оправданными для моделей на 7–8 млрд параметров.

## Когда что использовать

**Ollama**

- Внутренние инструменты
- Небольшое число одновременных запросов
- Быстрое прототипирование

**TGI**

- Контейнеризованные среды
- Команды, которым нужно структурированное логирование
- Управляемые продакшен-развёртывания

**vLLM**

- API-сервисы
- Большое число одновременных запросов
- Максимум токенов на каждый доллар

## Выводы

На одной RTX 4090 с Llama‑3.1‑8B в FP16:

- vLLM показал наибольшую устойчивую пропускную способность.
- TGI обеспечил сбалансированную производительность и инструменты для продакшена.
- Ollama пожертвовал максимальной загрузкой GPU ради простоты.

Выбор стека инференса — не косметика. Он определяет структуру затрат и поведение при масштабировании.

Для задач на арендованных потребительских GPU эффективность батчинга существенно влияет на экономику.
