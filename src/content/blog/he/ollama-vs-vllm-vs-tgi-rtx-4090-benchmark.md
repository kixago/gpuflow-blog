להריץ מודל משלכם זה רק חצי מהעבודה.

אחרי שסיימתם fine‑tuning, כפי שמפורט ב[מדריך ל-Fine‑Tuning פרטי של LLM](/he/private-llm-fine-tuning-guide/), ההחלטה הבאה היא תפעולית: איך מגישים את המודל ביעילות?

האינפרנס קובע:

- את העלות לטוקן
- את ההשהיה תחת עומס
- את יעילות הניצול של ה-GPU
- אם חומרה צרכנית בכלל מתאימה לפרודקשן

הבנצ'מרק הזה משווה בין שלושה סטאקים נפוצים לאינפרנס:

- Ollama
- vLLM
- Hugging Face Text Generation Inference (TGI)

המטרה היא לא העדפה אישית. המטרה היא מדידה.

---

## סביבת הבדיקה

**חומרה**

- GPU: NVIDIA RTX 4090 (24GB VRAM)
- CPU: מעבד צרכני בסדר גודל של Ryzen עם 16 ליבות
- RAM: 64GB DDR5
- אחסון: NVMe SSD
- CUDA: 12.1
- דרייבר NVIDIA: 550 ומעלה

**מודל**

- `meta-llama/Llama-3.1-8B`
- דיוק: FP16 (ללא קוונטיזציה ל-4 ביט)
- חלון הקשר: 4096 טוקנים

**תנאי הבנצ'מרק**

- פרומפט קלט של 512 טוקנים
- יצירת פלט של 128 טוקנים
- פענוח greedy (temperature = 0)
- ללא speculative decoding
- ללא tensor parallelism
- הפעלה חמה בלבד (המודל נטען מראש לפני המדידה)
- 8 זרמי בקשות מקבילים (היכן שיש תמיכה)

כל הבדיקות רצו על מכונה נקייה, בלי עומסי רקע. כל מדידה היא ממוצע של חמש הרצות.

## תוצאות

### 1. Ollama

Ollama שם את הפשטות במקום הראשון. ההתקנה מינימלית, והמודלים יורדים אוטומטית.

```bash
ollama run llama3
```

אפשרויות ההגדרה של התנהגות ה-batching או של אסטרטגיית התזמון מוגבלות.

#### ביצועים מדודים (RTX 4090, FP16)

- **תפוקה בזרם יחיד:** 62–74 טוקנים/שנייה
- **תפוקה ב-8 זרמים:** 95–108 טוקנים/שנייה
- **השהיה עד הטוקן הראשון:** 720–980 ms
- **צריכת VRAM שנצפתה:** 14–17GB

#### תצפיות

- ניצול ה-GPU השתנה תחת מקביליות.
- מעבר ל-4 זרמים, התפוקה לא גדלה באופן ליניארי.
- אין פקדים חשופים לאופטימיזציה מתקדמת של batching.

Ollama עובד באמינות לפיתוח מקומי ולשירותים עם תעבורה נמוכה. תחת עומס מקבילי רציף, הוא לא מנצל את ה-GPU עד הסוף.

---

### 2. vLLM

vLLM נבנה בשביל תפוקה. המימוש של PagedAttention משפר את יעילות ה-KV cache תחת בקשות מקבילות.

התקנה:

```bash
pip install vllm
```

הפעלה:

```bash
python -m vllm.entrypoints.openai.api_server \
  --model meta-llama/Llama-3.1-8B \
  --dtype float16
```

#### ביצועים מדודים (RTX 4090, FP16)

- **תפוקה בזרם יחיד:** 92–104 טוקנים/שנייה
- **תפוקה ב-8 זרמים:** 185–215 טוקנים/שנייה
- **השהיה עד הטוקן הראשון:** 360–480 ms
- **צריכת VRAM שנצפתה:** 20–22GB

#### תצפיות

- ניצול ה-GPU נשאר מעל 95% תחת עומס.
- Continuous batching שיפר את יעילות הגדילה.
- ההשהיה נשארה יציבה בכל הזרמים המקבילים.

vLLM השיג את התפוקה הרציפה הגבוהה ביותר לכל שעת השכרה.

---

### 3. Hugging Face Text Generation Inference (TGI)

TGI הוא שרת אינפרנס לפרודקשן שרץ בקונטיינר.

```bash
docker run --gpus all \
  -p 8080:80 \
  ghcr.io/huggingface/text-generation-inference:latest \
  --model-id meta-llama/Llama-3.1-8B
```

#### ביצועים מדודים (RTX 4090, FP16)

- **תפוקה בזרם יחיד:** 78–88 טוקנים/שנייה
- **תפוקה ב-8 זרמים:** 150–176 טוקנים/שנייה
- **השהיה עד הטוקן הראשון:** 510–690 ms
- **צריכת VRAM שנצפתה:** 21–23GB

#### תצפיות

- הביצועים היו עקביים וצפויים.
- התפוקה גדלה טוב יותר מאשר ב-Ollama, אבל פחות מאשר ב-vLLM.
- התקורה התפעולית גבוהה יותר בגלל סביבת הקונטיינרים.

TGI מציע פקדים וניטור לפרודקשן, אבל לא סוחט את התפוקה המקסימלית מ-4090 יחיד.

## ההשלכות על העלות ב-GPU מושכר

במרקטפלייסים של GPU, השכרת RTX 4090 עלתה בספטמבר 2026 בערך $0.30–$0.46 לשעה, תלוי בפלטפורמה ובביקוש. פירוט מלא תמצאו כאן:

- [השוואת מחירי השכרת GPU 2026](/he/gpu-rental-pricing-comparison-2026/)
- [העלות האמיתית של השכרת GPU](/he/hidden-fees-in-gpu-rental/)

נניח:

- השכרה ב-$0.45 לשעה
- 500,000 טוקנים שנוצרים
- 8 זרמים מקבילים

לפי התפוקה החציונית שנמדדה:

**vLLM (כ-200 טוקנים/שנייה)**  
500,000 / 200 = 2,500 שניות ≈ 41–42 דקות  
עלות ≈ $0.31

**Ollama (כ-100 טוקנים/שנייה)**  
500,000 / 100 = 5,000 שניות ≈ 83–84 דקות  
עלות ≈ $0.63

כשלעצמו, ההפרש בעלות לא דרמטי. הוא מצטבר בקנה מידה.

ב-50 מיליון טוקנים ביום, יעילות התפוקה משפיעה ישירות על גודל צי ה-GPU ועל משך ההשכרה.

### להריץ את הבנצ'מרק הזה בעצמכם

כדי לשחזר את המדידות האלה, אתם צריכים מכונה בשליטתכם, שעליה תוכלו להתקין ולהגדיר כל שרת. מרקטפלייסים שמשכירים קונטיינרים עם גישת SSH, כמו Vast.ai או RunPod, מתאימים לזה.

אם אתם רק רוצים לנסות מודלים שמוגשים דרך Ollama על RTX 4090 בלי להגדיר כלום, ב-[GPUFlow](https://gpuflow.app/he/marketplace) הספקים מריצים Ollama, ואתם שוכרים גישה דרך מפתח API תואם OpenAI, עם חיוב לפי שנייה. שם אי אפשר להחליף את שרת האינפרנס, אז זה מתאים לשימוש במודלים ולא לבנצ'מרק של השרתים.

מכיוון שההשכרה היא לפי שעה, יעילות האינפרנס משפיעה ישירות על העלות. ההבדל בין 100 ל-200 טוקנים לשנייה הופך משמעותי בעומסים רציפים.

## הקשר הפריסה

אם אתם שוכרים GPU לפי שעה, יעילות האינפרנס קובעת ישירות את יעילות העלות. את החישובים אנחנו עושים במאמר [GPU לפי שעה או API לפי טוקן](/he/hourly-gpu-vs-per-token-api/).

התפוקה משפיעה על:

- כמה שעות השכרה עבודה מסוימת צריכה
- כמה GPUs אתם צריכים בשביל התעבורה שלכם
- החשיפה לחוסר יציבות של המארח
- המרווח התפעולי

כרטיסי GPU צרכניים נשארים משתלמים כלכלית למודלים בגודל 7B–8B, כשמשלבים אותם עם סטאק אינפרנס יעיל.

## סיכום

על RTX 4090 יחיד שמריץ Llama‑3.1‑8B ב-FP16:

- vLLM השיג את התפוקה הרציפה הגבוהה ביותר.
- TGI סיפק ביצועים מאוזנים עם פקדים לפרודקשן.
- Ollama העדיף פשטות על פני ניצול מקסימלי של ה-GPU.

הבחירה בסטאק האינפרנס היא לא עניין קוסמטי. היא קובעת את מבנה העלויות ואת אופן הגדילה.

בעומסים שרצים על GPUs צרכניים מושכרים, יעילות ה-batching משפיעה באופן מהותי על הכלכליות.
