모델을 직접 돌리는 것은 절반일 뿐입니다.

[프라이빗 LLM 파인튜닝 가이드](/ko/private-llm-fine-tuning-guide/)에서 설명한 파인튜닝을 마치면 다음은 운영의 문제입니다. 모델을 어떻게 효율적으로 서빙할 것인가입니다.

추론이 결정하는 것은 다음과 같습니다.

- 토큰당 비용
- 부하 상황의 지연 시간
- GPU 활용 효율
- 소비자용 하드웨어를 프로덕션에 쓸 수 있는지 여부

이 벤치마크는 널리 쓰이는 추론 스택 세 가지를 비교합니다.

- Ollama
- vLLM
- Hugging Face Text Generation Inference (TGI)

목표는 선호가 아니라 측정입니다.

## 테스트 환경

**하드웨어**

- GPU: NVIDIA RTX 4090 (24GB VRAM)
- CPU: 16코어 Ryzen급 소비자용 프로세서
- RAM: 64GB DDR5
- 스토리지: NVMe SSD
- CUDA: 12.1
- NVIDIA 드라이버: 550+

**모델**

- `meta-llama/Llama-3.1-8B`
- 정밀도: FP16 (4비트 양자화 없음)
- 컨텍스트 윈도: 4096토큰

**벤치마크 조건**

- 입력 프롬프트 512토큰
- 출력 생성 128토큰
- 그리디 디코딩 (temperature = 0)
- 추측 디코딩 없음
- 텐서 병렬화 없음
- 웜 스타트만 측정 (측정 전에 모델을 미리 로드)
- 동시 요청 스트림 8개 (지원하는 경우)

모든 테스트는 백그라운드 작업이 없는 깨끗한 머신에서 실행했습니다. 각 측정값은 5회 실행의 평균입니다.

## 결과

### 1. Ollama

Ollama는 단순함을 우선합니다. 설치가 간단하고 모델도 자동으로 내려받습니다.

```bash
ollama run llama3
```

배칭 동작이나 스케줄링 전략을 조정할 수 있는 설정은 많지 않습니다.

#### 측정 성능 (RTX 4090, FP16)

- **단일 스트림 처리량:** 초당 62–74토큰
- **8스트림 처리량:** 초당 95–108토큰
- **첫 토큰 지연 시간:** 720–980 ms
- **관측된 VRAM 사용량:** 14–17GB

#### 관찰 내용

- 동시 요청 시 GPU 활용률이 오르내렸습니다.
- 스트림이 4개를 넘자 처리량이 선형적으로 늘지 않았습니다.
- 고급 배칭 최적화를 위한 설정이 노출되어 있지 않습니다.

Ollama는 로컬 개발과 트래픽이 적은 서비스에서는 안정적으로 동작합니다. 하지만 동시 부하가 계속되면 GPU를 완전히 활용하지 못합니다.

---

### 2. vLLM

vLLM은 처리량을 위해 설계되었습니다. PagedAttention 구현 덕분에 동시 요청에서 KV 캐시 효율이 높아집니다.

설치:

```bash
pip install vllm
```

실행:

```bash
python -m vllm.entrypoints.openai.api_server \
  --model meta-llama/Llama-3.1-8B \
  --dtype float16
```

#### 측정 성능 (RTX 4090, FP16)

- **단일 스트림 처리량:** 초당 92–104토큰
- **8스트림 처리량:** 초당 185–215토큰
- **첫 토큰 지연 시간:** 360–480 ms
- **관측된 VRAM 사용량:** 20–22GB

#### 관찰 내용

- 부하 중 GPU 활용률이 95% 이상으로 유지되었습니다.
- 연속 배칭 덕분에 확장 효율이 좋아졌습니다.
- 동시 스트림 전반에서 지연 시간이 안정적이었습니다.

대여 시간 1시간당 지속 처리량은 vLLM이 가장 높았습니다.

---

### 3. Hugging Face Text Generation Inference (TGI)

TGI는 컨테이너 기반의 프로덕션 추론 서버입니다.

```bash
docker run --gpus all \
  -p 8080:80 \
  ghcr.io/huggingface/text-generation-inference:latest \
  --model-id meta-llama/Llama-3.1-8B
```

#### 측정 성능 (RTX 4090, FP16)

- **단일 스트림 처리량:** 초당 78–88토큰
- **8스트림 처리량:** 초당 150–176토큰
- **첫 토큰 지연 시간:** 510–690 ms
- **관측된 VRAM 사용량:** 21–23GB

#### 관찰 내용

- 성능이 일관되고 예측 가능했습니다.
- 처리량 확장은 Ollama보다 낫지만 vLLM에는 못 미쳤습니다.
- 컨테이너 런타임 때문에 운영 부담이 더 큽니다.

TGI는 프로덕션용 제어와 모니터링 기능을 제공하지만, 4090 한 장에서 최대 처리량을 끌어내지는 못합니다.

## 대여 GPU에서의 비용 차이

GPU 마켓플레이스에서 RTX 4090 대여료는 2026년 9월 기준 플랫폼과 수요에 따라 시간당 약 $0.30–$0.46입니다. 자세한 분석은 다음 글을 참고하십시오.

- [2026년 GPU 대여 가격 비교](/ko/gpu-rental-pricing-comparison-2026/)
- [GPU 대여의 실제 비용](/ko/hidden-fees-in-gpu-rental/)

가정:

- 시간당 대여료 $0.45
- 생성 토큰 500,000개
- 동시 스트림 8개

측정된 처리량의 중간값을 사용하면 다음과 같습니다.

**vLLM (초당 약 200토큰)**  
500,000 / 200 = 2,500초 ≈ 41–42분  
비용 ≈ $0.31

**Ollama (초당 약 100토큰)**  
500,000 / 100 = 5,000초 ≈ 83–84분  
비용 ≈ $0.63

이 차이만 놓고 보면 크지 않습니다. 하지만 규모가 커지면 누적됩니다.

하루 5천만 토큰을 처리한다면 처리량 효율이 필요한 GPU 수와 대여 시간을 직접 좌우합니다.

### 이 벤치마크를 직접 돌려 보기

이 측정을 재현하려면 각 서버를 설치하고 설정할 수 있도록 직접 제어할 수 있는 머신이 필요합니다. Vast.ai나 RunPod처럼 SSH 접속이 되는 컨테이너를 빌려주는 마켓플레이스라면 가능합니다.

아무것도 설정하지 않고 RTX 4090에서 Ollama로 서빙되는 모델만 써 보고 싶다면, [GPUFlow](https://gpuflow.app/ko/marketplace)의 제공자들이 Ollama를 실행하고 있으며 OpenAI 호환 API 키로 접근을 대여할 수 있습니다. 요금은 초 단위로 과금됩니다. 다만 추론 서버를 바꿀 수는 없으므로, 서버 벤치마크가 아니라 모델을 사용하는 용도입니다.

대여는 시간 단위이므로 추론 효율이 비용에 바로 영향을 줍니다. 꾸준히 돌아가는 워크로드에서는 초당 100토큰과 200토큰의 차이가 의미 있게 커집니다.

## 배포 관점

GPU를 시간 단위로 빌린다면 추론 효율이 곧 비용 효율입니다. 구체적인 계산은 [시간제 GPU와 토큰당 과금 API 비교](/ko/hourly-gpu-vs-per-token-api/)에서 다룹니다.

처리량이 영향을 주는 것은 다음과 같습니다.

- 작업 하나에 필요한 대여 시간
- 트래픽을 감당하는 데 필요한 GPU 수
- 호스트 불안정성에 노출되는 정도
- 운영 마진

효율적인 추론 스택과 함께라면 7B–8B 모델에서는 소비자용 GPU가 여전히 경제적입니다.

## 언제 무엇을 쓸까

**Ollama**

- 내부 도구
- 낮은 동시성
- 빠른 프로토타이핑

**TGI**

- 컨테이너 기반 환경
- 구조화된 로깅이 필요한 팀
- 관리형 프로덕션 배포

**vLLM**

- API 서비스
- 높은 동시성
- 달러당 최대 토큰

## 결론

RTX 4090 한 장에서 Llama‑3.1‑8B를 FP16으로 실행했을 때:

- vLLM이 가장 높은 지속 처리량을 기록했습니다.
- TGI는 프로덕션용 제어 기능과 함께 균형 잡힌 성능을 보였습니다.
- Ollama는 GPU 활용 극대화보다 단순함을 택했습니다.

추론 스택 선택은 겉모습의 문제가 아닙니다. 비용 구조와 확장 방식이 여기서 정해집니다.

대여한 소비자용 GPU에 배포하는 워크로드라면 배칭 효율이 경제성에 실질적인 영향을 줍니다.

## 프로덕션에서는 어디서 돌릴까

이 글의 모든 벤치마크는 직접 소유한 인프라가 아니라 대여한 소비자용 하드웨어에서 진행했습니다.

파인튜닝을 하거나 자체 추론 서버를 돌리려면 로그인할 수 있는 머신을 빌리십시오. 아무것도 설정하지 않고 API로 Ollama 서빙 모델을 쓰고 싶다면 [GPUFlow](https://gpuflow.app/ko/marketplace)를 확인해 보십시오. 대여 요금은 초 단위로 과금되며, 카드로 구매한 크레딧으로 결제합니다.
