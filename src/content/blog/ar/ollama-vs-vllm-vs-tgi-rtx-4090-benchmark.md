تشغيل نموذجك الخاص ليس إلا نصف المعادلة.

بعد إتمام الضبط الدقيق، كما يشرح [دليل الضبط الدقيق الخاص للنماذج اللغوية](/ar/private-llm-fine-tuning-guide/)، يأتي القرار التشغيلي: كيف تخدم النموذج بكفاءة؟

الاستدلال هو ما يحدد:

- تكلفة كل رمز
- زمن الاستجابة تحت الحمل
- كفاءة استغلال GPU
- ما إذا كان العتاد الاستهلاكي صالحًا للإنتاج

يقارن هذا الاختبار ثلاث منظومات استدلال واسعة الانتشار:

- Ollama
- vLLM
- Hugging Face Text Generation Inference (TGI)

الهدف ليس التفضيل، بل القياس.

## بيئة الاختبار

**العتاد**

- GPU: NVIDIA RTX 4090 (24GB VRAM)
- المعالج: معالج استهلاكي من فئة Ryzen بـ 16 نواة
- الذاكرة: 64GB DDR5
- التخزين: NVMe SSD
- CUDA: 12.1
- تعريف NVIDIA: 550+

**النموذج**

- `meta-llama/Llama-3.1-8B`
- الدقة: FP16 (من دون تكميم 4‑bit)
- نافذة السياق: 4096 رمزًا

**ظروف الاختبار**

- موجّه إدخال من 512 رمزًا
- توليد مخرجات من 128 رمزًا
- فك ترميز جشع (temperature = 0)
- من دون فك ترميز تخميني
- من دون توازي الموترات (tensor parallelism)
- تشغيل دافئ فقط (النموذج محمّل مسبقًا قبل القياس)
- 8 تدفقات طلبات متزامنة (حيثما كان ذلك مدعومًا)

نُفّذت كل الاختبارات على جهاز نظيف بلا أي أعمال في الخلفية. وكل قياس هو متوسط خمس جولات.

# النتائج

## 1. Ollama

يعطي Ollama الأولوية للبساطة. التثبيت في حده الأدنى، والنماذج تُنزَّل تلقائيًا.

```bash
ollama run llama3
```

خيارات ضبط سلوك التجميع (batching) أو استراتيجية الجدولة محدودة.

### الأداء المقاس (RTX 4090، FP16)

- **الإنتاجية بتدفق واحد:** 62–74 رمزًا/ثانية
- **الإنتاجية بـ 8 تدفقات:** 95–108 رموز/ثانية
- **زمن أول رمز:** 720–980 ms
- **استهلاك VRAM الملاحظ:** 14–17GB

### ملاحظات

- تذبذب استغلال GPU تحت التزامن.
- لم يكن توسع الإنتاجية خطيًا بعد 4 تدفقات.
- لا توجد خيارات متاحة لتحسين التجميع المتقدم.

يعمل Ollama بموثوقية في التطوير المحلي والخدمات قليلة الحركة. لكنه تحت حمل متزامن مستمر لا يستغل GPU بالكامل.

---

## 2. vLLM

صُمّم vLLM من أجل الإنتاجية. وتحسّن آلية PagedAttention فيه كفاءة ذاكرة KV cache عند تزامن الطلبات.

التثبيت:

```bash
pip install vllm
```

التشغيل:

```bash
python -m vllm.entrypoints.openai.api_server \
  --model meta-llama/Llama-3.1-8B \
  --dtype float16
```

### الأداء المقاس (RTX 4090، FP16)

- **الإنتاجية بتدفق واحد:** 92–104 رموز/ثانية
- **الإنتاجية بـ 8 تدفقات:** 185–215 رمزًا/ثانية
- **زمن أول رمز:** 360–480 ms
- **استهلاك VRAM الملاحظ:** 20–22GB

### ملاحظات

- بقي استغلال GPU فوق 95% تحت الحمل.
- حسّن التجميع المستمر كفاءة التوسع.
- بقي زمن الاستجابة مستقرًا عبر التدفقات المتزامنة.

حقق vLLM أعلى إنتاجية مستدامة لكل ساعة استئجار.

---

## 3. Hugging Face Text Generation Inference (TGI)

TGI خادم استدلال إنتاجي يعمل داخل حاوية.

```bash
docker run --gpus all \
  -p 8080:80 \
  ghcr.io/huggingface/text-generation-inference:latest \
  --model-id meta-llama/Llama-3.1-8B
```

### الأداء المقاس (RTX 4090، FP16)

- **الإنتاجية بتدفق واحد:** 78–88 رمزًا/ثانية
- **الإنتاجية بـ 8 تدفقات:** 150–176 رمزًا/ثانية
- **زمن أول رمز:** 510–690 ms
- **استهلاك VRAM الملاحظ:** 21–23GB

### ملاحظات

- كان الأداء ثابتًا ويمكن توقعه.
- توسعت الإنتاجية أفضل من Ollama لكن دون vLLM.
- العبء التشغيلي أعلى بسبب بيئة تشغيل الحاويات.

يوفر TGI أدوات تحكم ومراقبة للإنتاج، لكنه لا يستخرج أقصى إنتاجية من بطاقة 4090 واحدة.

# الأثر على التكلفة عند استئجار GPU

في أسواق GPU، كانت تكلفة استئجار RTX 4090 تتراوح تقريبًا بين 0.30 و0.46 دولار في الساعة في سبتمبر 2026، حسب المنصة والطلب. اطّلع على التفاصيل في:

- [مقارنة أسعار استئجار GPU لعام 2026](/ar/gpu-rental-pricing-comparison-2026/)
- [التكلفة الحقيقية لاستئجار GPU](/ar/hidden-fees-in-gpu-rental/)

لنفترض:

- استئجارًا بسعر 0.45 دولار/ساعة
- توليد 500,000 رمز
- 8 تدفقات متزامنة

باستخدام الإنتاجية الوسيطة المقاسة:

**vLLM (~200 رمز/ثانية)**  
500,000 / 200 = 2,500 ثانية ≈ 41–42 دقيقة  
التكلفة ≈ 0.31 دولار

**Ollama (~100 رمز/ثانية)**  
500,000 / 100 = 5,000 ثانية ≈ 83–84 دقيقة  
التكلفة ≈ 0.63 دولار

فرق التكلفة ليس كبيرًا في حالة منفردة، لكنه يتضاعف مع الحجم.

فعند 50 مليون رمز يوميًا، تؤثر كفاءة الإنتاجية مباشرة في عدد وحدات GPU المطلوبة ومدة الاستئجار.

## أعِد هذا الاختبار بنفسك

لإعادة هذه القياسات تحتاج إلى جهاز تتحكم فيه، حتى تتمكن من تثبيت كل خادم وضبطه. والأسواق التي تؤجّر حاويات مع وصول SSH، مثل Vast.ai أو RunPod، تصلح لذلك.

وإن كنت تريد فقط تجربة نماذج يشغّلها Ollama على RTX 4090 من دون أي إعداد، فمزوّدو [GPUFlow](https://gpuflow.app/ar/marketplace) يشغّلون Ollama، وتستأجر أنت الوصول عبر مفتاح API متوافق مع OpenAI مع فوترة بالثانية. لا يمكنك هناك تبديل خادم الاستدلال، فالخدمة لاستخدام النماذج لا لقياس أداء الخوادم.

ولأن الاستئجار بالساعة، فكفاءة الاستدلال تؤثر مباشرة في التكلفة. والفرق بين 100 رمز/ثانية و200 رمز/ثانية يصبح ملموسًا في الأعمال المستمرة.

# سياق النشر

إن كنت تستأجر وحدات GPU بالساعة، فكفاءة الاستدلال تحدد مباشرة كفاءة التكلفة. نعرض الحسابات بالتفصيل في [GPU بالساعة أم API بالرمز](/ar/hourly-gpu-vs-per-token-api/).

تؤثر الإنتاجية في:

- عدد ساعات الاستئجار التي يحتاجها العمل
- عدد وحدات GPU التي تحتاجها لحجم حركتك
- مدى تعرضك لعدم استقرار المضيف
- الهامش التشغيلي

تبقى البطاقات الاستهلاكية مجدية اقتصاديًا لنماذج 7B–8B عند استخدامها مع منظومات استدلال فعالة.

# متى تستخدم كلًا منها

**Ollama**

- الأدوات الداخلية
- التزامن المنخفض
- النماذج الأولية السريعة

**TGI**

- البيئات القائمة على الحاويات
- الفرق التي تحتاج إلى سجلات منظمة
- عمليات النشر الإنتاجية المُدارة

**vLLM**

- خدمات API
- التزامن المرتفع
- أكبر عدد من الرموز لكل دولار

# الخلاصة

على بطاقة RTX 4090 واحدة تشغّل Llama‑3.1‑8B بدقة FP16:

- حقق vLLM أعلى إنتاجية مستدامة.
- قدّم TGI أداءً متوازنًا مع أدوات تحكم للإنتاج.
- فضّل Ollama البساطة على أقصى استغلال لـ GPU.

اختيار منظومة الاستدلال ليس أمرًا شكليًا، فهو يحدد هيكل التكلفة وسلوك التوسع.

وفي الأعمال التي تعمل على بطاقات استهلاكية مستأجرة، تؤثر كفاءة التجميع تأثيرًا جوهريًا في الجدوى الاقتصادية.

# أين تشغّل هذا في الإنتاج

أُجريت كل الاختبارات في هذا المقال على عتاد استهلاكي مستأجر لا على بنية تحتية مملوكة.

للضبط الدقيق أو لتشغيل خادم الاستدلال الخاص بك، استأجر جهازًا تستطيع الدخول إليه. ولاستخدام نموذج يشغّله Ollama عبر API من دون أي إعداد، اطّلع على [GPUFlow](https://gpuflow.app/ar/marketplace): تُفوتر عمليات الاستئجار بالثانية، ويُدفع ثمنها برصيد تشتريه ببطاقة مصرفية.
