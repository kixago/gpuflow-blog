モデルを自分で動かすことは、全体の半分にすぎません。

[プライベートLLMファインチューニングガイド](/ja/private-llm-fine-tuning-guide/)で解説したようにファインチューニングを終えたら、次は運用面の判断です。モデルをどうやって効率よく提供するかを決めなければなりません。

推論によって、次のことが決まります。

- トークンあたりのコスト
- 負荷がかかったときのレイテンシ
- GPUの利用効率
- コンシューマー向けハードウェアを本番で使えるかどうか

このベンチマークでは、広く使われている3つの推論スタックを比較します。

- Ollama
- vLLM
- Hugging Face Text Generation Inference（TGI）

目的は好みを語ることではなく、測ることです。

---

## テスト環境

**ハードウェア**

- GPU：NVIDIA RTX 4090（VRAM 24GB）
- CPU：16コアのRyzenクラスのコンシューマー向けプロセッサー
- RAM：64GB DDR5
- ストレージ：NVMe SSD
- CUDA：12.1
- NVIDIAドライバー：550以降

**モデル**

- `meta-llama/Llama-3.1-8B`
- 精度：FP16（4ビット量子化なし）
- コンテキストウィンドウ：4096トークン

**ベンチマークの条件**

- 512トークンの入力プロンプト
- 128トークンの出力生成
- グリーディデコード（temperature = 0）
- 投機的デコードなし
- テンソル並列なし
- ウォームスタートのみ（測定前にモデルを読み込み済み）
- 8本の同時リクエストストリーム（対応している場合）

すべてのテストは、バックグラウンドで何も動いていないクリーンなマシンで実行しました。各測定値は5回の実行の平均です。

# 結果

## 1. Ollama

Ollamaはシンプルさを最優先しています。インストールは最小限で、モデルは自動でダウンロードされます。

```bash
ollama run llama3
```

バッチ処理の挙動やスケジューリング戦略について、設定できる項目はわずかです。

### 実測性能（RTX 4090、FP16）

- **単一ストリームのスループット：** 62〜74トークン/秒
- **8ストリームのスループット：** 95〜108トークン/秒
- **最初のトークンまでのレイテンシ：** 720〜980ms
- **VRAM使用量（実測）：** 14〜17GB

### 所見

- 同時実行時にGPU使用率が上下した。
- 4ストリームを超えると、スループットが線形に伸びなくなった。
- 高度なバッチ処理の最適化を行う設定項目は公開されていない。

Ollamaは、ローカル開発やトラフィックの少ないサービスでは安定して動きます。ただし、同時アクセスによる負荷が続くと、GPUを使い切れません。

---

## 2. vLLM

vLLMはスループットを重視して設計されています。PagedAttentionの実装により、同時リクエスト時のKVキャッシュの効率が向上します。

インストール：

```bash
pip install vllm
```

起動：

```bash
python -m vllm.entrypoints.openai.api_server \
  --model meta-llama/Llama-3.1-8B \
  --dtype float16
```

### 実測性能（RTX 4090、FP16）

- **単一ストリームのスループット：** 92〜104トークン/秒
- **8ストリームのスループット：** 185〜215トークン/秒
- **最初のトークンまでのレイテンシ：** 360〜480ms
- **VRAM使用量（実測）：** 20〜22GB

### 所見

- 負荷がかかった状態でもGPU使用率は95%を超えたままだった。
- continuous batchingによってスケーリング効率が向上した。
- 同時ストリームが増えてもレイテンシは安定していた。

レンタル時間1時間あたりの持続スループットは、vLLMが最も高くなりました。

---

## 3. Hugging Face Text Generation Inference（TGI）

TGIはコンテナで動く本番向けの推論サーバーです。

```bash
docker run --gpus all \
  -p 8080:80 \
  ghcr.io/huggingface/text-generation-inference:latest \
  --model-id meta-llama/Llama-3.1-8B
```

### 実測性能（RTX 4090、FP16）

- **単一ストリームのスループット：** 78〜88トークン/秒
- **8ストリームのスループット：** 150〜176トークン/秒
- **最初のトークンまでのレイテンシ：** 510〜690ms
- **VRAM使用量（実測）：** 21〜23GB

### 所見

- 性能は安定しており、予測しやすかった。
- スループットの伸びはOllamaより良かったが、vLLMには及ばなかった。
- コンテナランタイムがあるぶん、運用のオーバーヘッドは大きい。

TGIには本番向けの制御機能や監視機能がありますが、RTX 4090 1枚の性能を最大限まで引き出すことはできません。

# レンタルGPUでのコストへの影響

GPUマーケットプレイスでのRTX 4090のレンタル料金は、2026年9月時点でサービスと需要に応じて1時間あたりおよそ$0.30〜$0.46です。詳しい内訳は次の記事をご覧ください。

- [2026年版 GPUレンタル料金の徹底比較](/ja/gpu-rental-pricing-comparison-2026/)
- [GPUレンタルの本当のコスト](/ja/hidden-fees-in-gpu-rental/)

前提条件：

- レンタル料金$0.45/時
- 生成トークン数500,000
- 同時ストリーム8本

実測スループットの中央値を使うと、次のようになります。

**vLLM（約200トークン/秒）**  
500,000 / 200 = 2,500秒 ≈ 41〜42分  
コスト ≈ $0.31

**Ollama（約100トークン/秒）**  
500,000 / 100 = 5,000秒 ≈ 83〜84分  
コスト ≈ $0.63

この差は単体で見れば大きくありません。しかし、規模が大きくなるほど積み重なります。

1日5,000万トークンになれば、スループットの効率が、必要なGPUの台数とレンタル時間に直接影響します。

## このベンチマークを自分で試すには

この測定を再現するには、各サーバーをインストールして設定できる、自分で管理できるマシンが必要です。Vast.aiやRunPodのように、SSHでアクセスできるコンテナを貸し出すマーケットプレイスなら対応できます。

何も準備せずに、RTX 4090上のOllamaで動くモデルを試してみたいだけなら、[GPUFlow](https://gpuflow.app/ja/marketplace)という選択肢があります。GPUFlowではプロバイダーがOllamaを動かしており、OpenAI互換のAPIキーを通じて利用します。課金は秒単位です。推論サーバーを入れ替えることはできないので、モデルを使うためのサービスであり、サーバーのベンチマークには向きません。

レンタルは時間単位なので、推論の効率がそのままコストに影響します。毎秒100トークンと毎秒200トークンの差は、継続的なワークロードでは無視できないものになります。

# 運用の観点から

GPUを時間単位で借りているなら、推論の効率がそのままコスト効率を決めます。具体的な計算は[時間課金のGPUとトークン課金のAPI](/ja/hourly-gpu-vs-per-token-api/)で検討しています。

スループットは次の点に影響します。

- ジョブに必要なレンタル時間
- トラフィックをさばくのに必要なGPUの台数
- ホストが不安定になった場合の影響の大きさ
- 運用上の余裕

効率のよい推論スタックと組み合わせれば、7B〜8Bクラスのモデルでは、コンシューマー向けGPUは今でも経済的に十分成り立ちます。

# それぞれの使いどころ

**Ollama**

- 社内ツール
- 同時アクセスが少ない用途
- すばやいプロトタイピング

**TGI**

- コンテナ化された環境
- 構造化されたログが必要なチーム
- 管理された本番デプロイ

**vLLM**

- APIサービス
- 同時アクセスが多い用途
- 1ドルあたりのトークン数を最大化したい場合

# まとめ

RTX 4090 1枚でLlama‑3.1‑8BをFP16で動かした場合：

- 持続スループットはvLLMが最も高かった。
- TGIは本番向けの制御機能を備え、バランスのとれた性能だった。
- OllamaはGPUの最大活用よりもシンプルさを優先していた。

推論スタックの選択は見た目の問題ではありません。コスト構造とスケーリングの挙動を決めるものです。

レンタルしたコンシューマー向けGPUにデプロイするワークロードでは、バッチ処理の効率が採算に大きく影響します。
